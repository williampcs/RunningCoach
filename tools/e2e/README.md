# 網頁實測（E2E）

用 Playwright 開網頁版、接模擬上游（`tools/mock-upstream.ts`），照使用者的操作點一遍並檢查結果。不需要任何金鑰。

## 準備

```bash
npm install
# 1. 模擬上游（LLM、Intervals.icu、同步服務、Open-Meteo），埠 8788
npm run dev:mock
# 2. 建置網頁版，Intervals.icu、同步服務與天氣都指向模擬上游；開著測試模式（功能開關 testmode，verify-ui-round1 用得到）
cd apps/web && VITE_FEATURES=testmode VITE_INTERVALS_BASE_URL=http://127.0.0.1:8788/intervals \
  VITE_SYNC_URL=http://127.0.0.1:8788/sync \
  VITE_WEATHER_BASE_URL=http://127.0.0.1:8788/weather npx vite build && cd ../..
# 3. 開建置好的網頁版，埠 4173
npx vite preview --port 4173 --strictPort -c apps/web/vite.config.ts apps/web
```

模擬上游與 preview 要在背景一直開著。改了網頁的程式要重新建置（第 2 步）；改了 `tools/mock-upstream.ts` 要重開模擬上游。

## 執行

```bash
node tools/e2e/verify-races.cjs      # 一個
for f in tools/e2e/verify-*.cjs; do echo "$f: $(node $f 2>&1 | tail -1)"; done   # 全部
```

最後一行印出 `ALL OK` 或 `SOME CHECKS FAILED`，上面是每一項檢查的結果。截圖放在 `$E2E_OUT`（預設是系統暫存目錄下的 `running-coach-e2e`），不進版控；改了畫面時看截圖確認版面。

環境變數（都有預設值）：`E2E_URL`（preview 的網址）、`E2E_MOCK`（模擬上游）、`E2E_OUT`（截圖）。Playwright 先找專案的，找不到時用雲端開發環境預先裝好的。

注意：

- 模擬上游的「今天」是台北時間；跨日前後（UTC 16:00 左右）需要日期對得上的腳本會先把時區設成 `Asia/Taipei`。
- 每個腳本用新的瀏覽器 context，等同第一次使用；不會互相影響，但同時跑多個會共用模擬上游的同步資料。
- 切換分頁、打開設定或說明用 `env.cjs` 的 `go(page, 名稱)`：設定與說明是蓋在分頁上的面板（12.17），手機上會蓋住底部的分頁；面板開著時底下的頁面是 inert，關閉時會先滑出，`go()` 會等它移除。分頁的名稱是「對話」「回報」「紀錄」「計畫」「選手」（12.28，開關開著與關著都一樣）。
- 設定的第一層是清單，點進去才是欄位（12.28）：進到某一項用 `settings(page, "AI 教練")`（「訓練紀錄」「天氣」「多裝置同步」「密碼鎖」「資料」「測試模式」「重置」「系統狀態」）；設定好模擬上游的 AI 與 Intervals.icu 用 `setupMock(page, { mock, intervals, timeZone })`。模型名稱、Athlete ID、時區在各項的「進階」裡；很多說明收在 ⓘ（按鈕的名稱就是說明的標題）。
- 存好了、同步完成是畫面下方的小提示（`.toast`，三秒後消失）；同步失敗或要使用者動手的才留在原地（`.notice`）。
- 功能開關（規格 12.25）：一般的建置（第 2 步）只開 `testmode`（測試模式；正式版關著，設定頁看不到測試模式的卡片，由 `verify-environments.cjs` 的正式版建置檢查），其他開關全關，既有的腳本檢查的是關著時的行為；開著時的功能由自己建置的腳本檢查（例如 `verify-multisport.cjs`），或建置時加上 `VITE_FEATURES=multisport`（`all` 是全開）。
- 模擬上游在請求帶 `cache_control` 時模擬 Prompt Caching（5 分鐘內寫過的前綴算讀取），回傳快取的讀與寫；`/_mock/requests` 的每筆模型請求附上回傳的用量（`usage`）。
- 對話說“…改成 400 m × 8”時，模擬的教練先看課表，再用 `edit_planned_session` 把第一堂閾值課改成 8×400 m（整週的檢查有新的提醒時寫理由再改）。
- 模擬上游的「今天」傍晚有一趟騎車（課表外的運動），騎車有自己的閾值心率、心率區間、FTP 與功率區間。
- 模擬上游另有 4 天前、8 天前的騎車（都不到 90 分鐘、負荷 60 以下，開關關著時不觸發「前一天騎很久」）；對話說“幫我排跑步和騎車的課表”會排一週跑步＋騎車（第一次故意有跨運動的警告，寫理由再存），“幫我排只騎車的課表”只排騎車，“剛騎完”記下騎車的體感（工具清單有單車的課時）。
- 新功能請加一個腳本或在既有的腳本加檢查，並更新上表。
